# Testing Overview

## Backend (Java)
- **Test Framework**: JUnit 5 (`spring-boot-starter-test`) with Spring TestContext support.
- **Integration Tests**: Most tests are integration‑style, booting the Spring context with an in‑memory H2 database. They cover:
  - Authentication flows (registration, login, PIN changes)
  - Transaction lifecycle (deposit, transfer, withdrawal)
  - KYC document handling and admin approval
  - Fee calculation engine and idempotency handling
  - Audit logging and security filters (rate limiting, JWT validation)
- **Test Coverage**: The CI scan reports **123 tests run with 0 failures**. Coverage is not explicitly measured in the repository, but given the breadth of integration tests, core business logic is exercised.
- **Test Organization**: Tests live under `src/test/java/com/novawallet/novawallet_api/` mirroring the package structure of the main code.

## Frontend (Flutter)
- **Default Widget Test**: `test/widget_test.dart` generated by `flutter create`. No additional UI or unit tests are present yet.
- **Testing Gap**: The mobile client lacks unit tests for providers, integration tests for API calls, and widget tests for the various screens defined in the UI hand‑offs. This is a target for future work.

## Recommendations
- **Add Coverage Plugin**: Integrate JaCoCo Maven plugin to generate an `lcov.info` file, enforce a minimum coverage threshold (e.g., 80% as per ECC testing rule).
- **Expand Flutter Tests**: Write unit tests for Riverpod providers, mock Dio responses, and widget tests for critical flows (registration, login, transfer).
- **CI Enforcement**: Update the GitHub Actions workflow to fail the build if coverage drops below the threshold and to run Flutter tests.
