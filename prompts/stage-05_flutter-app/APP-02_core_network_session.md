# APP-02 — Core: generated API client, auth/session, error mapping, config 🔒

**Area:** novawallet-app · **Needs:** APP-01 · **Contract:** `docs/api/openapi.json`, `docs/api/CONTRACT.md`, `docs/api/ERROR_CODES.md`

---
Read `novawallet-app/AGENTS.md` §3, §6, §7 and `docs/api/CONTRACT.md` completely.

Do:
1. **Generate the API client** from `docs/api/openapi.json` (openapi-generator for dart-dio or an equivalent) into `lib/core/api/generated/` (committed, regenerated by `make api`). Wrap it in hand-written repositories — screens never touch generated classes.
2. **Dio setup:** base URL from config, timeouts, headers (`X-App-Version`, `X-Device-Id`, `X-Request-Id`, `Accept-Language`), interceptors: auth header, **refresh-once** with a single in-flight refresh and queued requests, redacted debug logging, retry with backoff for idempotent GETs only, no auto-retry on money POSTs, `Idempotency-Key` helper.
3. **Error mapping:** sealed `AppFailure` from the error envelope and `ERROR_CODES.md`; one table mapping each backend code → the user-facing message exactly as the designs word them (check P01–P06, G05, C06, C07, F03 etc.); unknown → generic with request id.
4. **App config** at start (`GET /app/config`): maintenance (P05), update required (P06), feature flags, legal versions; cached.
5. **Session:** secure token storage, device id, `SessionController` (unknown → unauthenticated → locked → authenticated), restore at start, forced sign-out on refresh failure (C06), logout wipes tokens + drift cache. Inactivity lock → PIN screen (C02) state machine, lifecycle observer (background > N seconds → locked), FLAG_SECURE plumbing via platform channel.
6. **Connectivity** service and an `OfflineBanner`/"back online" signal for P01, P02, P09.
7. Router skeleton (go_router, typed routes from `SCREEN_INDEX.md`, guards for session/lock/KYC/feature flags, deep-link table). Placeholder pages for every route that name the screen code.
8. Local DB (drift) skeleton for cached lists; clear-on-logout; no secrets in it.
9. Tests: refresh queueing and loop prevention, every error code mapping, session/lock state machine with fake clock, guard redirects, config gates.

Acceptance: gates pass; app starts against the sandbox backend, logs in a seeded user (using a temporary debug login screen that is deleted in APP-04), restores session after restart, and shows maintenance/update screens when the backend flags are toggled.
